# Bug Report: B-167 (更新路由规则空包覆盖灾难)

## 表层症状 (Symptoms)
SSR-Plus 更新 `ip_data` 或 `gfw_data` 数据时，如果发生网络不通、运营商拦截或 404，但恰好 wget 命令仍然返回退出代码 0（或成功生成了一个空包/截断文件），则系统原有的稳定数据会被完全清除覆盖。导致终端设备的规则路由大范围瘫痪。

## 根因诊断 (Root Cause)
位于 `update.lua` 中的逻辑仅仅校验了 `new_md5 == old_md5` 以及 `wget` 的退出码 `sret == 0`。
如果在非预期的状况下产生了一个 0 字节或者极短错误响应体（例如 404 HTML 页），脚本不会有任何防御，直接执行：
`luci.sys.exec(\"cp -f /tmp/ssr-update.\" .. type .. \" \" .. file)`。

## 解决方案 (Resolution)
采用防御深度原则和 MECE 分析：
在校验完 MD5 并获取实际的文件行数之后 (`wc -l`)，拦截 `icount < 10` 的异常包。
此时不仅禁止替换本地文件，还触发 `-1` 返回码和 Error 级别诊断日志，防止灾难扩大。

## 补丁边界
`luci-app-ssr-plus/root/usr/share/shadowsocksr/update.lua`
